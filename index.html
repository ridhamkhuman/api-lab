What is an API? (easy)

API means Application Programming Interface. In plain words: a menu of URLs a server offers so other apps can ask for data or do actions.

Restaurant analogy (remember this)

  • You = the customer (your app / Postman / browser)
  • Waiter = the API (takes your order exactly as the kitchen allows)
  • Kitchen = the server + database
  • Menu = list of endpoints (URLs) like /users, /orders
  • Order ticket = your HTTP request (method + URL + auth + body)
  • Food on the plate = the response (usually JSON data)

You do not walk into the kitchen. You only talk through the waiter (API) using the menu rules.

Parts of every API request

If you understand these 5 pieces, Postman will feel easy.

1

URL (endpoint)

The address of the resource. Example:

https://jsonplaceholder.typicode.com/users/1
  • https:// — protocol (secure HTTP)
  • jsonplaceholder.typicode.com — server (host)
  • /users/1 — path (which resource: user id 1)
  • ?_limit=3 — query params (filters / options)
2

Method (verb)

What you want to do with that URL:

  • GET — read / fetch
  • POST — create new
  • PUT / PATCH — update
  • DELETE — remove

Same URL + different method = different action.

3

Headers

Extra info about the request. Common ones:

  • Accept: application/json — “please reply in JSON”
  • Content-Type: application/json — “my body is JSON”
  • X-Api-Key: … — your API key
  • Authorization: Basic … or Bearer …
4

Body

The data you send (mostly for POST / PUT / PATCH). Usually JSON:

{
  "title": "API Lab",
  "body": "Hello",
  "userId": 1
}

GET usually has no body.

5

Response

What comes back:

  • Status code — 200 OK, 401 Unauthorized, 404 Not Found…
  • Body — JSON data, error message, or empty
  • Time — how long the call took (ms)
★

What is JSON?

JSON is a simple text format for data. Keys in quotes, values can be text, numbers, true/false, lists, or nested objects.

{
  "name": "Ridham",
  "active": true,
  "skills": ["API", "Postman"]
}

How to use this playground (step by step)

This UI matches Postman. Do this once and you will understand real Postman too.

  1. Pick a request on the left — start with “GET · Users list”. It fills method + URL for you.
  2. Check the method dropdown — GET means “please give me data”.
  3. Look at the URL bar — that is the endpoint address.
  4. Open Params — optional filters like _limit=3 (only return 3 items).
  5. Open Authorization — choose No Auth / API Key / Basic / Bearer when needed.
  6. Open Headers — usually Accept: application/json is enough for GET.

  8. Press Send — look at status (green = success) and the JSON response below.

Authorization — full details

Servers need to know who you are before giving private data. These are the 3 types you will see most often.

Type 1

API Key

What it is: a long secret string (like a password for your app), created in a vendor dashboard (Stripe, Google Maps, company portal, etc.).

How it is sent: usually a header. Sometimes a query param (less preferred).

X-Api-Key: your_real_key_here
# or
Authorization: Api-Key your_real_key_here

In Postman: Authorization tab → Type = API Key → Key = X-Api-Key → Value = paste key → Add to = Header.

In this lab: use collection item GET · API Key demo. httpbin echoes headers so you can see the key was sent. Free public APIs below need no real key.

Never put production API keys in this website, Slack, email, or git commits. Use Postman Environments / Variables.

Type 2

Username + password (Basic Auth)

What it is: classic login. Username and password are encoded (Base64) and sent in one header.

Authorization: Basic cG9zdG1hbjpwYXNzd29yZA==
# that Base64 decodes to → postman:password

In Postman: Authorization → Basic Auth → fill Username & Password. Postman builds the header for you.

Demo credentials (safe, public test only):

  • Username: postman
  • Password: password
  • URL: https://httpbin.org/basic-auth/postman/password

Correct → 200. Wrong password → 401 Unauthorized.

Type 3

Bearer Token (OAuth / JWT)

What it is: after you login (or complete OAuth), the server gives a temporary token. You send that token on later requests instead of the password every time.

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...

In Postman: Authorization → Bearer Token → paste token. Or use OAuth 2.0 helper for company APIs.

Typical flow: Login (POST) → get token → save as {{token}} → send on GET /orders, etc. → when expired, login again.

So… can you “give me the API key”?

There is no single universal API key. Each product creates its own keys for your account. This lab uses demo-key-abc123 only to show the header shape — it is not a secret to a private system.

For learning GET data safely, use the free no-key APIs in the next section.

Status codes (read these every time)

The number in the response tells you if the call worked — before you even read the JSON.

Code Meaning What you should do
200OK — successRead the JSON body. Your GET/PUT/PATCH/DELETE worked.
201CreatedPOST created something. Often body includes new id.
204No ContentSuccess, but empty body (common after DELETE).
400Bad RequestYour JSON/params are wrong. Fix the body or query.
401UnauthorizedMissing/wrong API key, password, or token.
403ForbiddenLogged in, but not allowed for this resource.
404Not FoundWrong URL or id does not exist.
429Too Many RequestsRate limit. Wait and retry.
500Server ErrorProblem on their side. Retry later / contact API owner.

Real Postman UI map

Open Postman desktop/web — these zones match what you practiced here.

  1. Create a Workspace — shared place for your team’s requests.
  2. New → HTTP Request — blank request (like our playground).
  3. Method + URL bar — pick GET/POST/… and paste the endpoint.
  4. Params tab — query keys/values (auto-added to URL).
  5. Authorization tab — API Key / Basic / Bearer / OAuth 2.0.
  6. Headers tab — Content-Type, Accept, custom headers.
  7. Body tab — choose raw → JSON for POST/PUT/PATCH.
  8. Send — response appears below (Pretty / Raw / Preview).
  9. Save into a Collection — group “Users”, “Auth”, “Orders” for teammates.
  10. Environments — variables like {{baseUrl}} and {{apiKey}}. Switch Dev / QA / Prod without rewriting URLs.

  • Run DELETE → success status

Glossary — words you will hear at work

Quick meanings so meetings and docs feel less confusing.

Endpoint
A specific URL path on an API, e.g. /users/1.
REST
A common API style using HTTP methods + URLs for resources.
Resource
The “thing” you work with: user, post, order, invoice…
Payload / Body
Data you send in the request (usually JSON).
Query parameter
Options after ? in the URL, e.g. ?page=2.
Path parameter
Part of the path that changes, e.g. the 1 in /users/1.
Idempotent
Calling again has the same effect (GET, PUT, DELETE usually). POST often creates duplicates if repeated.
CORS
Browser security rule. Some APIs block browser calls; Postman desktop is not limited the same way.
Environment variable
Reusable value in Postman like {{apiKey}} so secrets stay out of the URL field.
Collection
Folder of saved requests you can share with your team.
Rate limit
Max calls allowed per minute/hour. Exceed → 429.
Base URL
Common start of all endpoints, e.g. https://api.company.com/v1.
